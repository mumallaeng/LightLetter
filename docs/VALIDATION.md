# 검증 기록과 한계

- BIT 파일은 현재 Vivado impl_1, Vitis 실행 설정 및 XSA 내부의 BIT와 SHA-256이 일치합니다.
- ELF는 현재 Vitis Debug 실행 대상과 dashboard 독립 빌드가 동일한 파일입니다.
- 현재 실행 소스로 ARM GCC 9.2(Vitis 2020.2) 빌드 성공.
- 호스트 테스트: 지연된 ACK/캡처, 타임아웃, 32비트 시간 rollover, 40비트 전력,
  소프트웨어 큐 초과, 일부 바이트만 받는 UART를 검증했습니다.
- 실제 C가 생성한 JSONL을 UI parser로 전달해 128개 전력과 HELLO BFSK WORLD+LF를 확인했습니다.
- 스냅샷 단독 RTL 테스트: 261개 읽기 PASS. 블록 중간 요청/valid 공백/저장값 유지/리셋 포함.
- 브라우저: 문자 공백/줄바꿈, 선택 bin 원본 power, DC 제외/로그 표시를 확인했습니다.
- 사용자 보드 관측: 10ms 패킷 간격에서 문자열 수신, FFT 스냅샷 갱신 및 DC 약22,000,000,
  bin8 약2,100, bin16 약2,700을 보고했습니다. 장시간/모든 환경에 대한 무결성 보장은 아닙니다.
- 저장된 구현 리포트: WNS=0.607ns, WHS=0.014ns, 모든 사용자 지정 타이밍 제약 충족.
  리포트는 복사한 기존 구현 결과이며 이 패키지로 전체 재합성을 수행한 결과는 아닙니다.
- tests/reference_rx는 기존 프로젝트에 있던 테스트 소스 보관용입니다. 최신 변경과의
  호환성/통과를 이번 패키징에서 주장하지 않습니다.
- 새 위치에서의 Vitis 전체 플랫폼 재생성 및 실제 보드 재다운로드는 별도 확인이 필요합니다.

실행 정책: 최대2Hz FFT, 128패킷 소프트웨어 큐, 패킷 우선 전송. UART 부하가 지속적으로
대역폭을 넘으면 큐가 찰 수 있습니다. UI의 큐 유실/PL 덮어쓰기 카운터를 확인하세요.
스냅샷은 FFT와 공통 리셋, 첫 valid=bin0, 블록당128개 출력이라는 전제를 사용합니다.
UI는 DC를 표시에서 제외할 뿐 수신 데이터나 RTL을 수정하지 않습니다.

## 이 폴더에서 프로젝트 생성 확인

- Vivado 2020.2로 create_project.tcl 실행 완료, BD validate 및 wrapper 생성 완료.
- 원본 BD와 재생성 BD의 21개 신호 연결, 6개 인터페이스 연결, 주소 맵, 외부 포트 및 저장된 IP 파라미터 일치 확인.
- 원본을 읽기 전용으로 열어 내보낸 recreate_bd.tcl에는 export 당시의 locked/out-of-date 안내가 남아 있습니다. 재생성된 프로젝트의 잠김을 뜻하지 않습니다.
- 재생성 로그에 PSU-1~4 DDR DQS 음수 skew 경고가 있습니다. 원본 PS 설정(-0.050/-0.044/-0.035/-0.100)을 그대로 보존했으며 이번 정리에서 값을 변경하거나 경고를 숨기지 않았습니다.
- RTL reset/clock 인터페이스 추론 및 GPIO 개별 핀 연결에 대한 경고도 로그에 남아 있습니다. 오류 없이 BD 검증이 끝났으며 전체 재합성·보드 시험을 대신하는 검사는 아닙니다.
- 원본 패키지에서 vivado/project를 생성해 검증했습니다. Git에는 생성 프로젝트와 workspace를 넣지 않습니다. clone 후 CREATE_VIVADO.cmd로 만드세요. 체크섬은 저장소에 배포한 소스·실행 파일·문서를 대상으로 합니다.
